# Teoría: Fundamentos de GitHub

## ¿Qué es Git?

Git es un sistema de control de versiones distribuido. Permite registrar cambios en archivos, recuperar versiones anteriores y colaborar con otras personas.

## ¿Qué es GitHub?

GitHub es una plataforma basada en Git que permite alojar repositorios y colaborar usando herramientas como:

- pull requests
- issues
- actions
- projects
- releases
- discussions

## Diferencia entre Git y GitHub

- Git: herramienta de control de versiones
- GitHub: plataforma para alojar y colaborar sobre repositorios Git

## Conceptos clave

### Repositorio
Es el espacio donde vive el código, la documentación y el historial de cambios.

### Commit
Es una confirmación de cambios en el historial.

### Branch
Es una rama de trabajo independiente.

### Merge
Es la integración de cambios de una rama a otra.

### Pull Request
Es una solicitud para revisar e integrar cambios.

## Flujo básico de trabajo

1. Crear o clonar repositorio
2. Crear una rama
3. Hacer cambios
4. Crear commit
5. Hacer push
6. Abrir pull request
7. Revisar y hacer merge

## Buenas prácticas iniciales

- escribir mensajes de commit claros
- trabajar en ramas para cambios relevantes
- no trabajar directamente en `main` para cambios grandes
- revisar cambios antes de hacer push
- usar pull requests para colaborar

## Errores comunes

- hacer commits demasiado grandes
- usar mensajes de commit ambiguos
- mezclar varios cambios no relacionados
- trabajar siempre directo en `main`
